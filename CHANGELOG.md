# Changelog

## 0.3.0

**Breaking: the CLI is now `pickbits-os`, was `company-os`.**

If you installed 0.1.0 or 0.2.0 and scripted `npx company-os build`, change it to
`npx pickbits-os build`. The package name is unchanged — `@pickbitsai/company-os`
installs the same as before, and `npm i -D @pickbitsai/company-os` is still the
install line. Only the binary it puts on your PATH is renamed.

Why: an unrelated package called `company-os` is published on npm and ships a
binary of the same name. A bare `npx company-os` on a machine that had not already
installed this package resolved to that one instead. Scoping the package was never
enough to prevent it, because `npx` resolves the *bin* name globally and no owner is
attached. With the org prefix, the same mistake now fails to resolve rather than
running an unrelated program.

Unchanged on purpose, so existing installs keep working:

- `company-os.config.mjs` — the config filename
- `<!-- generated by company-os` — the marker the build reads before overwriting a file
- `# company-os:` — the crontab marker the cron adapter parses
- the `company-os` schemaPrefix on published status files
